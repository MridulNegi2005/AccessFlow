# First real audio path: WAV to confirmed mock effect, 15 September 2026

This records Package 3 item 1 from `docs/reviews/CLAUDE_REVIEW_2026-09-15.md`: raw WAV
through actual ASR, the controller, real model reasoning, to a confirmed mock tool effect,
run through the existing evaluation harness. `docs/results/ASR_LOCAL_2026-09-15.md` measured
the ASR adapter in isolation; this measures the full controller path.

## Scenario

`scenarios/live_dev/audio_correction.json` (id `live-dev-audio-correction-01`). One `audio`
input event references the committed fixture `tests/fixtures/audio/synthetic_pause_correction.wav`
(script: "Book Tuesday. [1.5 s pause] Actually, Wednesday at five."; provenance in
`docs/feedback/PROVENANCE.md`). No `proposals` or `reasoning_steps` are scripted for it on
purpose: offline-fake mode has nothing to substitute for ASR and fails with `ValueError`
instead of silently accepting a supplied transcript.

`Scenario.path` resolution: `src/accessflow/evaluation/scenarios.py` now resolves a relative
`audio` payload `path` against the scenario JSON file's own directory (not the process's
working directory) before validation. This makes the committed path resolve identically
regardless of where `accessflow.cli` is invoked from; verified by loading the scenario both
from the repo root and from an unrelated working directory, and covered by
`tests/engine/test_scenarios.py::test_load_scenario_resolution_is_independent_of_process_cwd`.

## Command

```
$env:ACCESSFLOW_GROQ_API_KEY = "<from .env>"
$env:ACCESSFLOW_GROQ_MODEL   = "qwen/qwen3.8-27b"
$env:ACCESSFLOW_MAX_OUTPUT_TOKENS = "950"
.venv\Scripts\python.exe -m accessflow.cli replay scenarios\live_dev\audio_correction.json `
  --components local `
  --asr-model-path "<HF cache>\models--Systran--faster-whisper-base.en\snapshots\3d3d5dee26484f91867d81cb899cfcf72b96be6c" `
  --backend groq --request-timeout 30 `
  --output artifacts\live_audio\audio_correction_run<N>.jsonl
```

`--components local` wires `ProcessPerception` (real, process-isolated Faster Whisper) and
`HeuristicTurnPolicy` in place of the fakes; `--backend groq` wires `ModelReasoner` against
the hosted Qwen profile from `docs/PROFILES.md`. The ASR model directory is the one already
installed and measured in `docs/results/ASR_LOCAL_2026-09-15.md`
(`Systran/faster-whisper-base.en`, snapshot `3d3d5dee26484f91867d81cb899cfcf72b96be6c`).

Two runs, paced 100+ seconds apart per the Groq free-tier admission-control limit in
`docs/PROFILES.md`.

## What is real and what is mock, honestly

| Stage | Status |
|---|---|
| WAV file | Real, committed fixture; not synthesized at run time |
| ASR (Faster Whisper base.en, CPU int8) | Real inference, in the process-isolated worker subprocess (`accessflow.adapters.perception_worker`), not a supplied transcript |
| Turn/correction handling | Real `HeuristicTurnPolicy`; the transcript contains "Actually", which the policy classifies as `possible_correction`, exercising the same `final_correction` path as `text_correction.json`'s two-event case, from a single audio event |
| Reasoning | Real hosted call: Groq, `qwen/qwen3.8-27b`, `json_object` response mode, `ACCESSFLOW_MAX_OUTPUT_TOKENS=950` |
| Tool effect | Mock: `reserve_service_slot` is a developer-authored `MockEnvironment` write, not a live external system |
| Task oracle | Developer-authored (`day` slot + `final_basis: confirmed_tool_effect`); does not pin `hour`, because the fixture's script never states AM/PM (see Design note) |

## Design note: why the oracle does not assert `hour`

The fixture's spoken script is "Book Tuesday. Actually, Wednesday at five." — never "five
PM" or "17:00". `text_correction.json`'s scripted transcript event says "at five PM"
explicitly; the real WAV does not carry that information because it was never spoken. Pinning
`hour` to a specific value in the oracle would be scoring the model on information it was
never given, or worse, tuning the fixture script after the fact to manufacture a pass — both
of which `docs/reviews/CLAUDE_REVIEW_2026-09-15.md` (R9 item 5) warns against. The committed
hour is recorded above as real evidence of what the model inferred, not as a scored answer.

## Limitations, stated honestly

- One audio fixture, one tool, one turn. This is the first real path end to end, not
  coverage; `docs/SCENARIO_INVENTORY.md` still shows 1 of a planned 18 audio scenarios.
- Both runs used the same fixture and the same hosted model; this is not a held-out or
  cross-model result.
- The transcript is close to but not identical to the spoken script ("Book Tuesday Actually,
  Wednesday at 5" vs. "Book Tuesday. Actually, Wednesday at five.") — punctuation and number
  wording differ, consistent with the existing ASR measurement notes. No word error rate is
  claimed.
- Vision (`FrameEvent`) is still unconfigured on this path
  (`perception_worker._serve` constructs `LocalPerception(model_path=...)` with no vision
  provider); this result is audio only, per Package 3 item 1's scope.
- This does not measure premature-turn-completion / endpointing quality (R11's core research
  question); it demonstrates the pipeline is wired and produces a real, confirmed effect.
